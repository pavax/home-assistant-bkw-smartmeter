# BKW Smart Meter – Session notes (2026-05-22)

Context file to continue development later. Integration path: `custom_components/bkw_smartmeter/`.

## Project summary

Unofficial Home Assistant integration for [my.bkw.ch](https://my.bkw.ch/) energy data (OAuth PKCE + BKW metering API). Current version: **0.3.5**.

## Architecture (current)

```
config_flow (PKCE login, metering point, options)
    → __init__.py (BkwApi + coordinator)
    → BkwSmartMeterCoordinator (polls P1D on configurable interval)
    → sensors: Consumption (latest day), Consumption total
```

### API behaviour (discovered)

- BKW only returns **complete past portal days** — not the current calendar day until after midnight Swiss.
- **P1D** (day chart): local midnight `Europe/Zurich` → `21:59:59.999Z` on that date (CEST)  
  Example 21 May: `2026-05-20T22:00:00.000Z` → `2026-05-21T21:59:59.999Z`
- **PT15M** removed — was only used for “last 15 min” sensor; dropped per user request.
- Polling day: `get_polling_day()` from `get_query_window()` (yesterday until today’s slice is complete).

### Sensors

| Entity | Source | Notes |
|--------|--------|--------|
| Consumption (latest day) | P1D `latest_day_kwh` | Attribute `data_date` (e.g. `2026-05-21`) |
| Consumption total | Cumulative on config entry | Adds full day kWh once per new `data_date` |

### Auth

- OAuth client `mybkw-webapp`, PKCE, paste `code` from `https://my.bkw.ch/energy?code=...`
- Tokens on config entry: `access_token`, `refresh_token`, `expires_at`
- Refresh on demand before API calls (~10 min access token, 2 min margin)
- **Do not** store username/password — Keycloak password grant not applicable
- Keycloak may rotate refresh tokens; failed save → `invalid_grant` / “Maximum allowed refresh token reuse exceeded”

### Config entry persisted fields

- Tokens, `metering_point_code`, `data_type`
- `consumption_total_kwh`, `last_polled_day` (legacy: `last_interval_timestamp`)

### Options (Configure → Options)

- `data_type` (also copied to `entry.data`)
- `update_interval_minutes` — min **1**, default **15**, stored in `entry.options`
- Saving options reloads integration via `add_update_listener`

## Setup order (`__init__.py`)

1. Create coordinator, store in `hass.data`
2. `await coordinator.async_config_entry_first_refresh()` (data ready)
3. `async_forward_entry_setups` (sensors)
4. `entry.add_update_listener` → reload on options change

## Reset cumulative total (manual)

No UI yet. Edit `config/.storage/core.config_entries` for the `bkw_smartmeter` entry:

- **Zero, don’t re-add current day:** `consumption_total_kwh: 0`, `last_polled_day: "<current data_date>"`
- **Zero, re-add on next poll:** `consumption_total_kwh: 0`, remove `last_polled_day`

Or remove and re-add integration.
